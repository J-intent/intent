## 0. 战略定位：不打无准备之仗

### 0.1 与 Python 的关系：寄生 → 共生 → 替代（按序推进）

| 阶段 | 关系 | 标志能力 |
|---|---|---|
| 寄生期（v3.x） | Intent 调用 Python 生态 | I2 Python 互操作桥：`import python.requests` 直接用 |
| 共生期（v4.0-beta） | 双方各有不可替代层 | 契约系统 + BIM 领域库 + 自有包生态起步 |
| 替代期（v4.0+） | 特定场景下不再需要 Python | 该领域「Intent 原生包」覆盖 80% 常用需求 |

**战略结论：不要从零建生态（那是用 1 个人对抗 30 年）。I2 是整份路线图里 ROI 最高的单个任务。**

### 0.2 成熟度定义（可判定的终局）

> 「能用 Intent 写出、并持续维护一个 10 万行级生产系统，且团队中没有语言设计者也能干活。」

拆成五条硬标准（Phase 8 验收）：
1. 类型系统能防住 70% 的运行时错误（渐进类型 + 契约双重防线）
2. 依赖/构建/测试/发布链路完整，第三方可无摩擦参与
3. 性能在数值计算场景达到 CPython 的 0.8 倍（JIT 后）
4. 调试体验不弱于 pdb（事后调试 + 剖析 + 覆盖率）
5. 文档与社区到「陌生人能提第一个 PR」的程度

### 0.3 总线原则

- **契约优先**：Python 靠测试和注释表达意图，Intent 把意图前移到签名——这是唯一必须在每一期都强化的差异化
- **反膨胀**：每期配「不做清单」（见各期），砍掉的需求比砍掉的功能多
- **判定驱动**：每个任务有命令级判定，无判定的任务不进路线图
