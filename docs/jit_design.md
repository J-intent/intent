# Intent JIT 设计（M3a · 2026-10-19）

> 目标：数值计算场景达到 CPython 的 0.5x（v4.0-beta，M3c），最终 0.8x（v4.0 LTS，M3 下）。
> 现状：VM ≈ 4.3x 于树遍历解释器，fib(25) ≈ 788ms vs CPython ≈ 300ms ≈ **0.38x**。
> 本文是 M3b/M3c 的实施依据；任何方案变更先改本文档，再动代码（零漂移纪律）。

---

## 1. 问题与约束

| 约束 | 说明 |
|---|---|
| 无外部编译器 | 本机无 gcc/clang/msvc（I3a 已实证）；方案不能依赖运行期 C 编译 |
| 语义一致 | JIT 不得改变可观察语义（契约、异常、隐式返回、双引擎对照 vm_diff 必须保持全绿） |
| 可选开启 | 默认关闭，`--jit` 显式启用；关闭时零开销（热路径不加判断以外的东西） |
| 反膨胀 | 只做「数值核」子集；类/闭包/生成器/协程不 JIT（走解释器），不追求全语言覆盖 |

## 2. 候选方案对比

| 方案 | 做法 | 预期收益 | 风险 | 结论 |
|---|---|---|---|---|
| A. 原生代码生成 | 字节码 → C → 编译 → ctypes 调用 | 最高（≥1x） | **无编译器**；依赖宿主工具链 | ✗ 本机不可行，且违背零依赖 |
| B. 字节码模板特化 | 按运行时类型特化指令（int-int 加法内联等） | 中（~1.5-2x vs 现 VM） | 改动面大、收益有上限（仍是解释循环） | 备选 |
| **C. 热点函数转译成 Python** | 热函数 AST → Python 源码 → `exec` → 直接调用 | **高**（生成代码即 CPython 原生速度） | 子集限制、类型守卫、栈帧语义 | **选定** |
| D. 字节码缓存（AOT） | 编译产物落盘复用 | 省启动编译 | 不解决执行速度 | M3 下的退路（`.intentc`） |

**选型：C（热点函数转译为 Python 源码）**。理由：宿主就是 CPython——把 Intent 热函数翻成等价的 Python 函数，等于借 CPython 的 C 实现跑数值核；零外部依赖、确定性、可逐函数回退。

## 3. 架构

```
execute_function(func, args)
  ├─ jit_enabled 且 func.name 在 jit_cache?
  │    ├─ 命中特化且实参类型匹配 → 调 Python 编译产物（裸 int/float/str/bool）
  │    └─ 类型不匹配 → deopt：本次走解释器（不淘汰缓存）
  └─ 未命中 → 解释执行 + 调用计数 +1
       └─ 计数 ≥ HOT_THRESHOLD → 尝试编译（子集检查 → 生成 Python 源码 → exec）
            └─ 编译失败（不在子集）→ 标记 not_jittable，永不重试
```

- **热点阈值**：`HOT_THRESHOLD = 1000`（fib25 的递归调用远超阈值，编译收益可覆盖成本）。
- **特化粒度**：函数级，按「实参类型签名」做特化键（如 `fib(Int)`）；最多缓存 2 个签名，超出不再编译（防缓存膨胀）。
- **值表示**：编译产物只处理裸 Python `int/float/bool/str/None`；进入/离开 JIT 边界时做 RuntimeValue ↔ 原生值转换（边界转换不计入热路径）。
- **递归**：JIT 函数内的自递归直接调自身（不经过解释器）；对其他已编译函数按名字直调，未编译函数回退到解释器桥（`_jit_call_slow`）。

## 4. 可 JIT 子集（M3b 首版）

| 支持 | 不支持（走解释器，编译失败即标记） |
|---|---|
| `let/let mut` 标量、算术/比较/逻辑、`if/else`、`while`、`return` | 类/方法/dict/list 方法、闭包捕获、生成器、协程 |
| 本模块函数调用（含自递归）、内置白名单（abs/min/max/len…） | 契约子句里的复杂表达式（requires 在 JIT 包装层照常执行） |
| 隐式返回（块尾表达式值） | 异常/`try`/`match`/`with`/`spawn` |

**语义守卫**：
1. 调用前跑 `requires`（与解释器同口径；违约抛 ContractViolation，JIT 不绕过契约）；
2. 返回值按返回标注做 `_check_type`（同解释器）；
3. 任一实参不是标量 → deopt 走解释器；
4. 子集外语法 → 编译期拒绝（显式标记 not_jittable，不静默半支持）。

## 5. 验收

| 任务 | 命令级判定 |
|---|---|
| M3b | `python src/mini_intent.py --jit tests/perf_check.intent` 退出 0，输出含 `fib(25) = 75025` 与 **JIT** 标记（标记证明走了 JIT 路径，防「未知 flag 照常执行」的真空通过） |
| M3c | `python benchmarks/run_benchmarks.py --jit` 退出 0，输出含 `0.5`（JIT 相对 CPython 的倍率 ≥0.5，低于目标非零退出） |
| 回归 | `--test` 全绿、vm_diff 全 MATCH；`--jit` 与不加 `--jit` 的输出逐位一致（perf_check 的 `Time:` 行除外，由 vm_diff 归一化） |

## 6. 风险与退路（对齐 ROADMAP R3）

| 风险 | 触发信号 | 退路 |
|---|---|---|
| 转译子集太小，fib 类代码覆盖不到 | M3b 后 fib25 提升 <1.2x | 扩大子集（先补列表下标/for 循环）或转方案 B（字节码特化） |
| 边界转换开销吃掉收益 | 小函数调用变慢 | 只在热点函数启用；阈值上调 |
| 语义偏差 | vm_diff DIVERGE 或测试红 | 立即回退解释器路径（JIT 是 opt-in，关掉即恢复） |
| 连续 2 轮无实质进展 | 熔断纪律 | 启用 AOT 退路：`.intentc` 缓存（M3 下），保证启动性能有交代 |

## 7. 里程碑

- **M3b**：`--jit` 开关 + 热点计数 + 子集转译（标量/算术/if/while/return/自递归）+ fib25 正确性与 JIT 标记；
- **M3c**：基准套件 `--jit` 模式 + 0.5x 门禁 + 回归对照（`--test`/vm_diff 全绿）；
- **M3 下（LTS）**：列表/字典热路径、内联小函数、AOT `.intentc` 缓存，冲 0.8x。
