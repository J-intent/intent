## 8.1 出生时就写下遗嘱

```intent
def process_file(path: String) {
    let f = open(path);
    defer { close(f); };
    
    // 处理文件...
    // 无论中间发生什么，close(f) 最后都会执行
};
```

`defer { close(f); }` 写在函数入口附近，执行在出口。

这是一个哲学性的设计：**资源的清理代码，写在获取资源的同时。**

你打开文件，就写下关闭它。你分配内存，就写下释放它。你开始一段关系，就想好如何告别。

海德格尔说"向死而生"——人的有限性不是缺陷，而是使生命有意义的条件。正因为会死，才需要认真活。

`defer` 就是这个思想的代码形式：正因为函数会结束，才需要写 `defer`。**结束不是意外，结束是函数的一部分。**

---

## 8.2 提前退出也不怕

```intent
def early_return(flag: Int) {
    let mut data = 0;
    defer { print("cleanup: data was ", data); };
    
    if flag { return; };
    data = 42;
};
```

即使提前 `return`，`defer` 也会执行。

你不需要在每一个 `return` 语句前手动加清理代码。`defer` 是一次性的承诺："无论从哪条路离开，我善后。"

道家说"功成身退，天之道也"——完成了使命就离开。`defer` 是"身退"的代码保证：你不带着资源泄露离开。

## 8.3 闭包：此心光明

```intent
def make_counter(start: Int) {
    let mut count = start;
    return fn(): Int {
        count = count + 1;
        return count;
    };
};

let counter = make_counter(0);
print(counter());  // 1
print(counter());  // 2
print(counter());  // 3
```

`make_counter` 返回了一个**闭包**——一个"携带诞生环境"的函数。

`count` 是 `make_counter` 的局部变量。按理说函数返回后它就死了。但闭包**保留了诞生时的世界**。`count` 还活着，`counter()` 每次调用都在这个保存的世界中递增。

王阳明说"此心光明，亦复何言"——这颗心无论走到哪儿，都是亮的。闭包携带诞生环境，无论被传递到哪儿，它都记得自己来自哪里。

这不只是技术特性——**闭包是"不忘初心"的程序形式。**

## 8.4 Yield：生生不息

```intent
def numbers() {
    let mut i = 0;
    while i < 5 {
        yield i;
        i = i + 1;
    };
};
```

`yield` 是生成器——函数不是一次性执行完，而是一点点"产出"值，让调用者每次取一个。

这是"生生不息"的哲学：《易经》说"生生之谓易"——创造力不是一次性的爆发，是持续的产出。

`yield` 在代码层面上实现了这种哲学：你可以 `for x in numbers()` 遍历一个无限的流（理论上）。不是算好了所有结果再返回——**算一个，给一个。**

道家说"道生一，一生二，二生三，三生万物"——生成不是一次的，是递进的。`yield` 让函数变成生成这个递进。

## 8.5 有限性的礼物

把这一章的四个概念放在一起看：

| 概念 | 哲学 |
|------|------|
| `defer` | 向死而生（结束使一切有意义） |
| 提前 return + defer | 功成身退（善始善终） |
| 闭包 | 此心光明（不忘初心） |
| `yield` | 生生不息（持续产出） |

这四个概念串联了一个完整的故事：

1. 你诞生在某个环境（闭包携带环境）
2. 你持续产出（yield 生生不息）
3. 你知道自己会结束（defer 向死而生）
4. 但你不是孤立的——你和世界相连（万物一体，第7章）
