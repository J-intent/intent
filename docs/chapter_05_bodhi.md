# 第5章：烦恼即菩提 — 错误是另一种正常

> **运行代码**：`python3 src/mini_intent.py examples/lesson_05_bodhi.intent`
> **哲学**：禅宗"烦恼即菩提"、斯多葛"控制你能控制的"
> **语法**：`Result<T,E>`、`?` 操作符、`try/catch/finally`

---

## 5.1 传统的恐慌

大多数编程语言中，错误处理是"恐慌模式"：

```javascript
try {
    let result = mayFail();
} catch (e) {
    // 恐慌处理
}
```

你不知道哪里会炸。你 `try/catch` 包裹一切。你的代码像走在雷区，每一步都在担心。

这种模式有三个问题：

1. **二分世界**：一个"正常路径"和一个"异常路径"。而现实中，错误和正常是连续的。
2. **控制流断裂**：catch 块跳出正常流程，你的思维被打断。
3. **责任模糊**：谁该catch？调用者？调用者的调用者？

---

## 5.2 Result：错误也是一种值

Intent 的核心理念：**错误就是另一种返回值。**

```intent
// Ok(value) 和 Err(reason) 是平等的两支
match result {
    Ok(value) => "成功了：" + str(value),
    Err(reason) => "出错了：" + reason,
};
```

`Ok` 和 `Err` 是同一个 `Result` 类型的两个变体。不存在"正常路径"和"异常路径"的二分——他们都是返回值。

禅宗说"烦恼即菩提"。烦恼不是要消灭的东西——认识了烦恼，烦恼本身就是智慧。

Ok 和 Err 是平等的。就像白天和黑夜，都是天空的自然状态。

---

## 5.3 `?` 操作符：平静地传播

```intent
def might_fail(): Result[Int, String] {
    return Err("除数不能为零");
};

def caller(): Result[Int, String] {
    let value = might_fail()?;  // ← 如果 Err，直接返回 Err
    return Ok(value * 2);
};
```

`?` 操作符的语义：如果是 Ok，拆包取值；如果是 Err，**平静地向上传播**。

你没有"恐慌"，没有"崩溃"，没有"抛异常"。你只是说：**这不是我能处理的，交给上一层。**

斯多葛哲学的核心：区分"我控制得了的"和"我控制不了的"。`?` 就是这个区分。

调用 `might_fail()` 时，`?` 说："这个函数可能返回错误，但我处理不了——我让调用者来决定。"

不是逃避责任，是**知道自己的边界**。

---

## 5.4 try/catch：最后的安全网

`?` 处理了大部分错误传播。但有些操作（比如除零）是运行时才能发现的：

```intent
try {
    let x = 1 / 0;
} catch {
    print("捕获到了错误！");
};
```

注意：catch 不需要 `catch(e)` 然后检查 e 的具体类型。能 catch 的就是被抓住了——你已经认识了它。

**你看到错误，你理解了它，你没有被它打败——你认识了它。** 这就是"烦恼即菩提"的最终转化。

---

## 5.5 finally：无论如何

```intent
try {
    // 可能失败的操作
} catch {
    // 处理错误
} finally {
    // 无论如何都会执行
};
```

`finally` 是最有哲学感的语法：**无论成功失败，善始善终。**

在循环中尤其美妙：

```intent
while try_count < 5 {
    try_count = try_count + 1;
    try {
        if try_count == 3 { let z = 1 / 0; };
        print("第", try_count, "次尝试：成功");
    } catch {
        error_count = error_count + 1;
        print("第", try_count, "次尝试：失败（但继续）");
    };
};
```

**受伤 ≠ 死亡。** 失败一次，不是人生的终结。计数器继续走，下一个循环开始。

---

## 5.6 一场修行（In a Loop）

```
尝试 5 次，失败 1 次
```

1/5 的失败率。一次除零。

在传统编程中，一次除零 = 程序崩溃 = 所有状态丢失 = 重新开始。

在 Intent 的 `try/catch in a loop` 中：一次除零 = 一次 catch = 计数器 +1 = 继续。

**禅宗说"烦恼就是菩提"，斯多葛说"控制你能控制的"。try/catch in a loop 就是把这两个哲学翻译成代码。**

你不能控制除零发生（控制不了），但你能控制：发生了怎么办、继续还是不继续、计数不计入。（控制得了的。）

---

## 5.7 练习：受伤后继续走

1. 写一个 `parse_int(s: String): Result[Int, String]`。如果 s 是 "123" 返回 Ok(123)，否则返回 Err("不是数字")。
2. 用 `?` 链式调用三个可能失败的函数。
3. 在 while 循环中放 try/catch，失败后继续。数一数成功了几次、失败了几次。

---

## 5.8 小结

| 语法 | 哲学 |
|------|------|
| `Result<T,E>` | Ok 和 Err 是平等的（错误是另一种正常） |
| `?` | 平静地传播（知道自己的边界） |
| `try/catch` | 烦恼即菩提（认识错误=转化错误） |
| `finally` | 善始善终（无论如何） |
| `try in a loop` | 受伤≠死亡（下一次循环继续） |
